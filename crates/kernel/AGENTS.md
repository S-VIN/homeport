Ядро приложения: механизмы, из которых собираются плагины. Ядро ничего не знает о подписках, серверах или правилах. Правила для авторов плагинов — plugins/AGENTS.md; здесь — устройство ядра и справка по API.

## Жизненный цикл

- **Host** блокирует каталог данных, открывает `rproxy-plugins.sqlite3` и держит текущий `Kernel`. Смена набора плагинов перезапускает ядро в том же процессе; окна и вкладки браузера продолжают работать и рисуют новое ядро. Остановка Host сериализована с restart/import и окончательна.
- **Kernel::start**: переключатели плагинов → зависимости → `setup` в порядке зависимостей → миграции → загрузка состояния → запуск mihomo → расписания → событие `Started`.
- **Запись** (`cx.write`) — один писатель: (1) синхронное замыкание над свежим снимком (copy-on-write ячеек, проверка владельца); (2) каскады удаления; (3) новый снимок → фрагменты всех плагинов → применение в mihomo (только выбор группы или полный конфиг); (4) коммит SQLite, при ошибке — прежний конфиг mihomo; (5) публикация снимка, перерисовка, события, расписания. Читатели берут снимок без блокировок.
- **Op** — действие с цепочкой обработчиков: ранг (`Specific` через `p.wrap` → `Default` → `Fallback`), вес заявки (`claim`), затем зависимый плагин раньше того, от кого зависит. Op с `JobSpec` — фоновая задача: прогресс, отмена, объединение или очередь по ключу.

## mihomo как сервис (`core.rs`)

- Домашний каталог `<data>/core`: кэш гео-списков (`rules/*.mrs`) и обновлённое ядро (`bin/mihomo` побеждает комплектное, `updates.rs`).
- Служебный SOCKS-вход `routed` идёт по обычным правилам: через него ядро и плагины скачивают то, что напрямую недоступно.
- Полосы проверок: N входов `checks-i`, у каждого группа `test-i`; `cx.core().lease(target)` берёт свободную, до `mihomo::CHECK_LANES`. Имена `test*`/`checks*` зарезервированы. Delay-тесты (`cx.core().probe`) идут без аренды и параллельно.
- Подписи (`core::Labels`): при каждой сборке конфига ядро собирает `Fragment.labels` (имя прокси, группы, слушателя или правила по `Rule::reported()` → слова пользователя) плюс DIRECT/REJECT; `cx.core().labels()` — `get`, `name`, `text`, `is_group`, `inbounds`.
- Слушатель, не занявший порт при старте, отмечается ошибкой, остальные работают; новый слушатель, который не стартует, отклоняет правку.
- TUN: `Core::restart` перезапускает единственное ядро с правами или без; `CoreStatus::tun_error` не даёт повторять запрос прав до явного off/on или restart (подробно — crates/mihomo/AGENTS.md).

## Конфигурация (`configuration.rs`)

Экспорт — явным действием в переносимый SQLite-файл; импорт проверяет схему и значения до подтверждения; временный снимок откатывает неудачный запуск. Постоянных бэкапов нет. `configuration::Profile` собирает такой же файл для другой установки — плагины не объявляют таблицы ядра сами. Native открывает системный файловый диалог, web передаёт файл по тому же WebSocket.

## Справка по API для плагинов

- **Состояние**: `p.list`, `p.collection`, `p.setting`, `p.editable_setting`, `p.live`; `p.data_dir()` / `cx.data_dir()` — `<data>/plugins/<id>`.
- **Списки**: `p.list(&RULES)` даёт таблицу, порядок, ops `Add`/`Save`/`Edit`/`Move`/`Remove` и события `Added`/`Saved`/`Removed`, которые называют свой список (`Add::new(&RULES, rule)`). `Edit::new(&RULES, id, |r| …)` правит внутри транзакции. Второй список того же типа — `.table("rules_archive")`.
- **Живое состояние**: `cx.set_live`, `cx.update_live`, `cx.live`, `snap.live`; `let _busy = cx.mark_live(&BUSY, id)` — элемент уходит при drop guard. В `p.core` недоступно.
- **Настройки из UI**: `p.editable_setting(&S)` + `cx.update(key, &S, |s| …)` или ops `Set`/`Update` (op несёт само состояние).
- **Сервисы**: `p.service(name, spec, run)` перезапускается при смене `spec(snapshot)` (`None` — стоп); `.on_stop(...)` возвращает изменения системы, следующий запуск ждёт его; `.restart_on_error()` — повтор через 2 с … 5 мин, одна ошибка показывается один раз.
- **Фоновая работа**: обработчики `p.on`/`p.on_change` и действия UI — задачи плагина; ядро отменяет и ждёт их при остановке. Повторное событие: по умолчанию ещё один запуск, `.latest()` отменяет прежний, `.queued()` — по одному с самым новым. Ошибка `p.every` показывается один раз до успеха.
- **Актуальность**: `let input = cx.input(|snap| …)` до сети, `input.check(w)?` в финальной записи — устаревший результат тихо отменяется. `JobSpec::latest()` / `.queued()`; ключи задач локальны для плагина (`JobSpec::keyed(id, "Load subscription")`).
- **Миграции** — механизм для времени после релиза; до релиза не используются (схема меняется в создании БД, корневой AGENTS.md). Новое `Option<T>` или `#[serde(default)]` — ничего не нужно; обязательное поле — `#[column(default = "0")]`; остальное — `p.migrate(1, |sql| …)`. На новой установке версии отмечаются без запуска. Нечитаемая настройка уходит в `<имя>.broken` с уведомлением.
- **Переопределение UI**: `p.replace`, `p.wrap_view`, `p.hide` по id `плагин/имя`; опечатка останавливает запуск с перечнем вкладов.
- **Сеть**: `cx.core().routed_http()`; `cx.core().direct_or_routed("GitHub", |c| …)` — сначала напрямую. Мелочи: `random_bytes::<N>()`, `hex`, `now()`, `Hook::exclusive(id)` — решение одного плагина (второй отвечающий игнорируется с уведомлением); `cx.core().changes()` — ждать смены статуса ядра; `snap.first(&HOOK, &x)` — первый ответ хука с `Option`.
- **UI**: `cx.get`, `cx.submit(key, op)` (ключи локальны; op с `const SAVES: bool = true` включает «Saving…/Saved»), `cx.request::<Reply>(key)`, `cx.outcome(key)`, `cx.notify_with(text, "Undo", || op)`, `cx.setting(ui, label, &S, field, control)`, `cx.job_button(ui, icon, label, enabled, || op)`, `cx.run`, `cx.status_chip`. Нужны и ответ, и поведение задачи — держи результат в live-состоянии.

## Оболочка окна (`shell.rs`)

- Статус-бар: чипы (точка или иконка + короткий текст) слева, Activity и «Saving…/Saved» справа. В узком окне чип открывает поповер со своей панелью (нет панели — свою страницу; чужие панели — никогда) поверх страницы (тень, ограниченная высота, закрывается кликом снаружи и Esc), список под ним не сдвигается. От 960 pt панели — справа от страницы.
- Тосты плавают сверху поверх контента (страница не сдвигается): в узком окне под статус-баром, в широком — над колонкой панелей; до трёх, новые сверху. Иконка, заголовок, текст, крестик; у ошибки со страницей (`JobSpec::page`, `notify_error_at`) — «Open <страница>». Ошибка о странице, которая открыта, тостом не показывается — страница показывает её сама. Подтверждение уходит через 4 с, ошибка или Undo — через 8 с; наведение удерживает.
- Навигация снизу: иконка над подписью, активная вкладка — мягкая акцентная плашка, лишние страницы — в More.
- Settings: Import… и Export… в заголовке; импорт проверяет файл, показывает имя и размер и требует Replace settings (Cancel и Esc отменяют). Карточки General (тема, Quit), секция каждого плагина с `SETTINGS_SECTIONS` под его именем, About. Без системного трея нативное приложение показывает Quit rproxy в General → Application; в вебе этой команды нет, постоянной кнопки Quit нет.
- Plugins: группы категорий, переключатели с доступными именами, Open… ведёт на страницу функции. Зависимости видны, только если не выполнены («Inactive · Needs Tests, which is off»); отложенное включение — бейдж «Restart required» и баннер с «Restart now».

## Тесты

`Host::start(vec![&PLUGIN, …], dir)`, затем `host.kernel().cx_for("id").call(op)` и `snapshot().get(&STATE)`; `host.kernel().idle().await` вместо `sleep`. Примеры — `tests/kernel.rs`, переход данных между версиями — `tests/migrations.rs`.
