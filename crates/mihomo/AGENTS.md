Типизированный конфиг mihomo (`Fragment` → `Config` → JSON), процесс ядра и контроллер.

## Правила

- Доступ плагинов к mihomo только типизированный: `Fragment` и типизированный API контроллера. Сырого JSON и «запасного выхода» нет.
- Ядро mihomo всегда одно, в том числе с TUN. Второго ядра, отдельных helper-бинарников, служб, setuid-копий и capabilities нет.

## Процесс

- Ядро запускается под внутренним режимом того же исполняемого файла `rproxy --core-supervisor` (`supervisor.rs`). Приложение держит lease: закрытие lease (выход или авария приложения) — супервизор останавливает и reap-ит ядро. Встраивающее приложение обязано обработать `supervisor::ARG` до создания runtime и вызвать `supervisor::configure`.
- Обычное ядро: lease — stdin супервизора. Windows Job создаётся до spawn; Linux PDEATHSIG — дополнительная защита.
- Контроллер: Unix-сокет на Linux/macOS, loopback TCP со случайным bearer-секретом на Windows и для ядра с TUN.
- Окружение Go (`GO_ENV`) ограничивает потоки и память ядра; значения из окружения побеждают.

## TUN (`elevation.rs`)

- Ядро с `Config::tun` запускает тот же супервизор через системный запрос прав: Polkit `pkexec` (Linux), диалог администратора (macOS), UAC (Windows). Права спрашиваются на каждое включение и перезапуск.
- Lease — loopback-соединение `--lease <порт> <файл-билет>`: билет из приватной папки сессии доказывает, что подключился запущенный нами процесс.
- Остановка: приложение выключает TUN через контроллер, супервизор шлёт SIGTERM с ограниченным ожиданием (Unix) и возвращает владельцу файлы, созданные root в `<data>/core`.
- Flatpak: `flatpak-spawn --host --watch-bus pkexec` по пути приложения на хосте (`app-path` из `/.flatpak-info`, разрешение `org.freedesktop.Flatpak`). AppImage: root запускает сам файл `$APPIMAGE`.
- Отказ в правах при включении отклоняет правку; при запуске с сохранённым TUN ядро стартует без туннеля (kernel: `CoreStatus::tun_error`).
