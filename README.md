# rproxy

Менеджер прокси для Linux, Windows и macOS (x64 и ARM64) с общим интерфейсом egui для нативного окна и браузера. Окно egui, хендлеры, планировщик и SQLite работают в одном процессе. Приложение само запускает комплектный mihomo 1.19.32 и управляет им через приватный Unix-сокет (Linux/macOS) или loopback-контроллер со случайным секретом (Windows).

## Установка на сервер и готовые приложения

- **VDS:** [Docker Compose с Caddy, HTTPS и Tinyauth](docker/README.md). После
  заполнения `.env` запуск — `docker compose up -d`. Образы скачиваются из GHCR;
  сборка на VDS не нужна. Для публичного HTTPS нужны два DNS-имени на IP сервера.
- **Desktop:** [платформы, пакеты и сборка](#сборки-приложения). Windows setup и
  portable, Linux AppImage/Flatpak/pacman, macOS DMG; везде x64 и ARM64.
- **GitHub Actions:** `Docker image` публикует amd64/arm64 в GHCR, `Desktop application`
  прикладывает пакеты к запуску Actions. Оба запускаются вручную или тегом `v*`.

## Запуск

Для первого запуска из свежего клона нужны Rust и Python 3.11+.
Бинарники mihomo для всех шести платформ хранятся в Git в `assets/mihomo/`.
Сгенерированные файлы `web/pkg` создаются при сборке. Из корня проекта:

```sh
python3 scripts/mihomo.py
python3 scripts/build.py
cargo run --locked
```

Нужный mihomo выбирается по ОС и архитектуре автоматически; подробности — в [инструкции сборки](#сборки-приложения).
После первоначальной сборки для запуска достаточно `cargo run --locked`.

Для запуска только веб-интерфейса выполните команду и откройте [rproxy на localhost](http://127.0.0.1:8080/).

```sh
cargo run --locked -- web
```

Для окна и браузера одновременно выполните `cargo run --locked -- desktop --listen 127.0.0.1:8080`. В обоих случаях один процесс владеет профилем, задачами и ядром. HTML, JS, WASM и WebSocket обслуживаются одним слушателем. Веб-управление доступно на loopback. Порт 20808 принимает проксируемый трафик, порт 8080 обслуживает интерфейс.

Браузер получает только «экран» на WASM без кода приложения: интерфейс выполняется в процессе rproxy. После изменений в `crates/remote` выполните `python3 scripts/build.py` (для оптимизированного бинарника — `python3 scripts/build.py --release`). Одна команда собирает WASM, обновляет файлы в `web/pkg` и встраивает их в исполняемый файл.

Для оптимизированной сборки используйте `cargo run --release --locked`. Для отдельного профиля — `cargo run --locked -- --data-dir /путь/к/каталогу`. Подписки и результаты сохраняются в `$XDG_DATA_HOME/rproxy/rproxy-plugins.sqlite3`, обычно это `~/.local/share/rproxy`. Прежняя база `rproxy.sqlite3` не используется и не изменяется. При первом запуске создаётся новая база и локальный HTTP/SOCKS5-вход на `127.0.0.1:20808`. Адрес, порт и авторизация редактируются на отдельной вкладке **Inbounds**.

## Первое подключение

1. Откройте **Subscriptions**, вставьте ссылку на HTTP(S)-подписку или прямую `vless://` и нажмите значок добавления либо Enter. Ссылка сохраняется, затем начинается загрузка.
2. В **Servers** подключитесь значком возле сервера или включите **Auto**. Укажите адрес входящего прокси в браузере или другой программе. Системные настройки прокси пользователь задаёт самостоятельно.
3. В **Tests** добавьте URL и ожидаемый HTTP-ответ, затем запустите проверку кнопкой **Check all servers**. Проверки используют отдельный маршрут и не переключают обычный трафик. Неуспех одного узла не прерывает остальные проверки.
4. В **Routing** добавьте правила **Via server**, **Direct** или **Block**. Побеждает первое совпадение. Поддерживаются домены с `*`, IP, CIDR и префиксы вида `192.168.*`. Если сервер не выбран, маршрут **Via server** блокирует запросы. Значок редактирования открывает шаблон; стрелки меняют порядок правил.

**Subscriptions** принимает списки VLESS в открытом виде и Base64, Xray JSON с VLESS, Shadowsocks и Hysteria 2, а также `proxies:` из Mihomo/Clash YAML. Импортируются исходящие узлы; слушатели, правила и контроллер задаются приложением. Неподдерживаемые параметры не отбрасываются молча. Подписки обновляются при запуске и по расписанию. Неудачная загрузка сохраняет прежний каталог и не мешает другим подпискам; корректная пустая подписка очищает свой каталог. Стрелки порядка, редактирование и удаление доступны в каждой строке.

**Auto** сохраняется между запусками. Выбор учитывает здоровье, рейтинг и приоритет подписки, перепроверяет кандидата перед переключением и использует задержку и лимиты против частых переключений. Три последовательных сбоя текущего сервера запускают поиск замены; неудачные кандидаты временно исключаются. Ручное подключение или отключение выключает **Auto**. Исключение выбранного сервера фильтром имени также отключает его, без неожиданного автоматического выбора.

Существующие поля **Routing**, **Inbounds** и **Settings** применяются после Enter или потери фокуса; переключатели и списки — сразу. Отдельных Save/Apply нет. Новые записи добавляются явно, удаление требует подтверждения. Подсказки действий и форматов доступны при наведении. Пустой пароль существующего защищённого входа сохраняет прежний пароль. Ошибки применения не стирают черновик слушателя. Занятый при запуске порт не мешает остальным входам; неисправный вход можно повторно включить после освобождения порта.

Строка статуса сверху показывает подключение, Auto и слушатель; нажатие открывает подробности (в широком окне они справа). **Activity** справа в строке статуса показывает фоновые задачи с прогрессом и кнопкой отмены. Фильтры имён открываются кнопкой **Filters** над списком серверов.

**Settings** управляет темой, периодами задач, автозапуском и плагинами. Произвольный интервал в секундах редактируется прямо в строке. При доступном системном трее закрытие окна оставляет маршрутизацию и расписание работающими. **Open rproxy** возвращает окно, **Quit** завершает оба процесса. Если окружение не предоставляет трей, закрытие окна завершает программу. На Linux (кроме Flatpak) настройка **Start at sign-in** создаёт пользовательскую XDG-запись для текущего исполняемого файла.

## Своя нода: VLESS server

Плагин **VLESS server** (по умолчанию выключен; включается в **Settings → Plugins**) принимает клиентов по VLESS поверх REALITY с транспортом XHTTP. Маскировка следует современным советам против DPI:

- **Self steal SNI.** Рукопожатие TLS — это рукопожатие настоящего сайта на вашем домене. Встроенный сайт работает на loopback-порту этой же машины и сам получает сертификат Let's Encrypt (проверка TLS-ALPN-01 проходит через тот же порт 443). Соединение без ключа клиента попадает на этот сайт, поэтому активное зондирование видит обычный веб-сервер. Можно указать и свой сайт (`host:port`, например nginx).
- **XHTTP** вместо голого TCP: данные идут обычными запросами HTTP/2.
- **Без фиксированных интервалов.** Паддинг и время жизни потоков задаются диапазонами. Ссылка клиента просит отпечаток браузера (`fp=chrome`) и явные диапазоны мультиплексирования (XMUX), чтобы клиент не открывал залп рукопожатий к одному SNI. rproxy-клиент применяет те же диапазоны к любой XHTTP-ссылке.
- На ноде включён сниффинг, поэтому доменные правила работают и для клиентов, присылающих IP.

Ссылку и QR-код для каждого клиента показывает страница плагина; удаление клиента отзывает доступ.

**Выходная нода** получается сочетанием настроек, отдельного режима нет:

1. Установите rproxy на сервер. Подписки не добавляйте; лишние плагины (Subscriptions, Auto select, Start at login и др.) выключите в **Settings → Plugins**.
2. Включите **VLESS server**, укажите домен (его A-запись указывает на сервер) и порт 443. Порты ниже 1024 требуют root или `CAP_NET_BIND_SERVICE` для комплектного бинарника mihomo (и для rproxy, если включён ответ на порту 80).
3. В **Routing** добавьте правило `*` → **Direct** (кнопка **Exit here** на странице VLESS server делает это за вас). Без него трафик клиентов идёт через выбранный на ноде сервер — так собирается промежуточная нода (каскад).
4. Для публичного управления используйте [защищённый Compose](docker/README.md). Без него запускайте `rproxy web` на `127.0.0.1` и заходите через SSH-туннель (`ssh -L 8080:127.0.0.1:8080 node`).

## Цепочка: Exit server

Плагин **Exit server** добавляет второй хоп: это устройство → выбранный сервер (вход) → выходной сервер → интернет. Вход — обычный выбранный вручную или через **Auto select** сервер; выход — один стабильный сервер, который добавляется ссылкой на отдельной странице **Exit server** и не смешивается с подписками. Сайты видят адрес выхода, а не входа. Если сервер не выбран или выход недоступен, трафик блокируется, а не уходит в обход выхода. Страница и панель подключения показывают путь и задержку через оба хопа; проверка повторяется каждые две минуты.

## Устройство проекта

Вся функциональность — плагины в `plugins/`, ядро в `crates/kernel`. Подробно: [архитектура](ARCHITECTURE.md), [как писать плагины и зоны интерфейса](PLUGINS.md), [дизайн-система](DESIGN.md).

| Путь | Назначение |
| --- | --- |
| `src/` | Точка входа: окно, трей, веб-сервер, список плагинов |
| `crates/kernel` | Плагины, состояние, действия, задачи, mihomo, оболочка окна |
| `crates/kit` | Тема, иконки, виджеты egui |
| `crates/mihomo` | Типизированный конфиг и управление ядром |
| `crates/remote` | Интерфейс в браузере: хост рисует, браузер показывает |
| `plugins/` | servers, subscriptions, format-uri/xray/clash, name-filters, routing, inbounds, health-checks, auto-select, exit-server, vless-server, autostart |
| `assets/` | Ядро mihomo, шрифты, логотипы |
| `docker/` | Compose, Caddy, Dockerfile и пример `.env` для VDS |
| `scripts/` | Сборка, упаковка, обслуживание mihomo и проверка Docker-авторизации |
| `.github/workflows/` | Два процесса CI: Docker image и Desktop application |

Плагины включаются и выключаются в **Settings → Plugins**; изменения применяются кнопкой **Restart now**.

## Проверки

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

Сквозные тесты (`tests/e2e.rs`, `tests/node.rs`) запускают настоящий mihomo на временных локальных адресах: форматы подписок через цепочку плагинов, загрузку и обновление, выбор сервера, маршруты, отклонение правки слушателя на занятый порт, HTTP/SOCKS5-авторизацию, проверки через изолированный маршрут, автовыбор, сохранение после перезапуска ядра, VLESS-ноду с клиентом (REALITY + XHTTP, сайт-приманка для зондов) и цепочку через выходной сервер. `crates/kernel/tests` проверяют механику ядра на тестовых плагинах, `crates/remote/tests` — передачу кадров интерфейса, в том числе декодирование под wasm32.

## Сборки приложения

**Actions → Desktop application → Run workflow** запускает шесть нативных сборок.
Также workflow запускается для тегов `v*`. Результаты — в Artifacts соответствующего
запуска Actions (публикация GitHub Release автоматически не выполняется).

| ОС | Архитектуры | Пакеты |
| --- | --- | --- |
| Windows | x64, ARM64 | NSIS setup.exe, portable.exe, portable.zip |
| Linux | x64, ARM64 | AppImage, Flatpak, pacman (.pkg.tar.zst) |
| macOS | Intel x64, Apple Silicon ARM64 | DMG |

Версия берётся из корневого Cargo.toml. Браузерный WASM собирается один раз и
передаётся всем desktop jobs. Каждый job берёт **свой** бинарник mihomo 1.19.32
из `assets/mihomo/<os>/<arch>/`, проверяет его SHA-256 по `manifest.json`,
компилирует программу и упаковывает её. Checkout получает только ядро выбранной
платформы; WASM job не загружает ядра. Тесты, Clippy и запуск готовых пакетов
не входят в GitHub-сборки и доступны локально.
Для каждого набора файлов создаётся SHA256SUMS. Сборки Linux используют Ubuntu
24.04 для совместимости с glibc 2.39+; Flatpak использует runtime 25.08.
AppImage использует графические библиотеки установленного Linux-десктопа
(X11/Wayland, xkbcommon, EGL/OpenGL); Flatpak получает их из runtime.

Windows setup устанавливается текущему пользователю без администратора.
Portable EXE распаковывается во временный каталог и хранит профиль в
`rproxy-data` рядом с EXE; portable ZIP хранит `data` рядом с бинарником
(маркер `portable.txt`). Переносите portable-профиль вместе с программой.

DMG содержит приложение для переноса в Applications и ad-hoc подпись,
не Developer ID/notarization. Windows-пакеты также не имеют сертификата подписи:
ОС может потребовать явного разрешения запуска скачанного приложения.
На macOS и Windows закрытие окна завершает приложение; трей и автозапуск
пока доступны только в Linux. В Flatpak автозапуск отключён, чтобы не записывать
неработающий путь из sandbox. AppImage использует постоянный путь APPIMAGE.

Профиль установленной версии: `%LOCALAPPDATA%\rproxy` на Windows,
`~/Library/Application Support/rproxy` на macOS, `$XDG_DATA_HOME/rproxy`
(обычно `~/.local/share/rproxy`) на Linux. Путь можно переопределить `--data-dir`.
Удаление Windows-программы сохраняет профиль.

### Локальная сборка

Нужны Python 3.11+, Rust из rust-toolchain.toml и системный C/C++ toolchain
(Windows: MSVC, macOS: Xcode command-line tools, Linux: GCC, pkg-config и
библиотеки X11/Wayland/EGL). Список пакетов Linux указан в desktop.yml.

```sh
python3 scripts/mihomo.py
python3 scripts/build.py --release
```

В репозитории уже есть все шесть бинарников mihomo. Проверка не требует сети;
при локальном запуске нужный бинарник выбирается автоматически.
На Windows используйте `python`. Все скрипты сборки написаны на Python.
`--native-only` пропускает сборку WASM, `--web-only` собирает только WASM.
`--no-default-features` даёт серверный бинарник без eframe, X11, Wayland и трея.
Флаг `--smoke-test --data-dir <временный каталог>` проверяет запуск ядра без окна.

Скрипт `scripts/package.py` запускается **на целевой ОС и архитектуре** после
release-сборки. CI устанавливает инструменты упаковки. Для ручной проверки пакетов
используйте `python scripts/package.py --check --os <ОС> --arch <архитектура>`.
Полная проверка каждой платформы требует соответствующего
runner, локальная проверка Linux её не заменяет.

Вся сборочная логика находится в четырёх Python-файлах:

- `scripts/build.py` — компиляция WASM и приложения. Утилита wasm-bindgen хранится
  в `.cache/wasm-bindgen`, отдельно от очищаемого Cargo-кэша, и сохраняется между
  запусками CI.
- `scripts/package.py` — создание и проверка установщиков и переносимых пакетов.
  Шаблоны NSIS, Linux desktop entry, Flatpak и macOS metadata находятся здесь;
  промежуточные файлы генерируются в игнорируемом `dist/`.
- `scripts/mihomo.py` — проверка и выбор комплектного ядра; `--update` обновляет
  бинарники по закреплённым URL и хешам в `assets/mihomo/manifest.json`.
- `scripts/test-docker-auth.py` — ручная сквозная проверка серверной установки.
