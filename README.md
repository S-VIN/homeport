# rproxy

Менеджер прокси для Linux, Windows и macOS (x64 и ARM64) с общим интерфейсом egui для нативного окна и браузера. Окно egui, хендлеры, планировщик и SQLite работают в одном процессе. Приложение само запускает комплектный mihomo 1.19.34 и управляет им через приватный Unix-сокет (Linux/macOS) или loopback-контроллер со случайным секретом (Windows).

## Установка на сервер и готовые приложения

- **VDS:** [Docker Compose с Caddy, HTTPS и Tinyauth](docker/README.md). После
  заполнения `.env` запуск — `docker compose up -d`. Образы скачиваются из GHCR;
  сборка на VDS не нужна. Для публичного HTTPS нужны два DNS-имени на IP сервера.
- **Desktop:** [платформы, пакеты и сборка](#сборки-приложения). Windows setup и
  portable-папка, Linux AppImage/Flatpak, macOS DMG; везде x64 и ARM64.
- **GitHub Actions:** только ручной запуск workflow `release` через **Run workflow**.
  Каждый пакет (Windows, Linux, macOS; x64 и ARM64) — отдельный артефакт-zip.
  Флажок **Publish the Docker image** дополнительно публикует образ amd64/arm64
  в GHCR. Тесты в workflow не запускаются.

## Запуск

Для первого запуска из свежего клона нужны Rust и Python 3.11+.
Бинарники mihomo для всех шести платформ хранятся в Git в `assets/mihomo/`.
Сгенерированные файлы `web/pkg` создаются при сборке. Из корня проекта:

```sh
python3 scripts/mihomo.py
python3 scripts/build.py
cargo run --locked
```

Нужный mihomo выбирается по ОС и архитектуре автоматически; подробности — в [инструкции сборки](#сборки-приложения).
После первоначальной сборки для запуска достаточно `cargo run --locked`.

Для запуска только веб-интерфейса выполните команду и откройте [rproxy на localhost](http://127.0.0.1:8080/).

```sh
cargo run --locked -- web
```

Режим задаёт одно слово: `rproxy` или `rproxy desktop` — окно, `rproxy background` — только трей (так запускает автозапуск), `rproxy web` — только веб-интерфейс. Остальное — переменные окружения: `RPROXY_LISTEN=IP:PORT` (адрес веб-интерфейса) и `RPROXY_DATA_DIR` (каталог профиля). Для окна и браузера одновременно выполните `RPROXY_LISTEN=127.0.0.1:8080 cargo run --locked`. В обоих случаях один процесс владеет профилем, задачами и ядром. HTML, JS, WASM и WebSocket обслуживаются одним слушателем. Веб-управление доступно на loopback. Порт 20808 принимает проксируемый трафик, порт 8080 обслуживает интерфейс.

Браузер получает только «экран» на WASM без кода приложения: интерфейс выполняется в процессе rproxy. После изменений в `crates/remote` выполните `python3 scripts/build.py` (для оптимизированного бинарника — `python3 scripts/build.py --release`). Одна команда собирает WASM, обновляет файлы в `web/pkg` и встраивает их в исполняемый файл.

Для оптимизированной сборки используйте `cargo run --release --locked`. Для отдельного профиля — `RPROXY_DATA_DIR=/путь/к/каталогу cargo run --locked`. Подписки и результаты сохраняются в `$XDG_DATA_HOME/rproxy/rproxy-plugins.sqlite3`, обычно это `~/.local/share/rproxy`. Прежняя база `rproxy.sqlite3` не используется и не изменяется. При первом запуске создаётся новая база и локальный HTTP/SOCKS5-вход на `127.0.0.1:20808`. Адрес, порт и авторизация редактируются на вкладке **Local proxy**.

## Первое подключение

1. Откройте **Subscriptions**, вставьте ссылку на HTTP(S)-подписку, прямую `vless://`, ключ Amnezia VPN (`vpn://`) или конфиг WireGuard/AmneziaWG (`[Interface]…`) и нажмите значок добавления либо Enter. Ссылка сохраняется, затем начинается загрузка.
2. В **Servers** подключитесь значком возле сервера или включите **Auto**. Укажите адрес входящего прокси в браузере или другой программе либо включите в **Local proxy** пункт **System proxy** (системные настройки прокси указывают на этот порт, если у него нет логина, и возвращаются при выключении или выходе) или **TUN mode** (TUN: весь трафик устройства, включая программы без настроек прокси).
3. В **Tests** добавьте URL и ожидаемый HTTP-ответ, затем запустите проверку кнопкой **Test all**. Проверки используют отдельный маршрут и не переключают обычный трафик. Неуспех одного узла не прерывает остальные проверки.
4. В **Routing** добавьте правила **Proxy**, **Direct** или **Block**. Побеждает первое совпадение. Тип правила выбирается слева в строке добавления: **Domain** (домены с `*`), **IP** (IP, CIDR, префиксы вида `192.168.*`), **GeoIP** (страна из списка или частные сети), **GeoSite** (`category-ru`, `youtube`…), **App**, **Inbound** (например, клиенты VLESS inbound) и **Everything**; гео-списки (списки MetaCubeX meta-rules-dat; ядро скачивает их при первом использовании и обновляет раз в сутки, кнопка **Update geo data** — сразу; число записей видно в строке правила, неизвестный список не ломает ядро). Если сервер не выбран, маршрут **Proxy** блокирует запросы. Значок редактирования открывает шаблон; стрелки меняют порядок правил.

**Subscriptions** принимает списки VLESS в открытом виде и Base64, Xray JSON с VLESS, Shadowsocks и Hysteria 2, `proxies:` из Mihomo/Clash YAML, конфиги WireGuard и AmneziaWG (1.0, 1.5, 2 и 3) и ключи Amnezia VPN `vpn://` с подключениями AmneziaWG, WireGuard, Xray и Shadowsocks (OpenVPN, IKEv2 и Cloak ядро не поддерживает; ключи Amnezia Premium и Free работают через сервис Amnezia и не поддерживаются). Импортируются исходящие узлы; слушатели, правила и контроллер задаются приложением. Неподдерживаемые параметры не отбрасываются молча. Подписки обновляются при запуске и по расписанию. Неудачная загрузка сохраняет прежний каталог и не мешает другим подпискам; корректная пустая подписка очищает свой каталог. Стрелки порядка, редактирование и удаление доступны в каждой строке.

**Auto** сохраняется между запусками. Выбор учитывает здоровье, рейтинг и приоритет подписки, перепроверяет кандидата перед переключением и использует задержку и лимиты против частых переключений. Три последовательных сбоя текущего сервера запускают поиск замены; неудачные кандидаты временно исключаются. Ручное подключение или отключение выключает **Auto**. Исключение выбранного сервера фильтром имени также отключает его, без неожиданного автоматического выбора.

Существующие поля **Routing** и **Settings** применяются после Enter или потери фокуса; переключатели и списки — сразу. Адрес и логин **Local proxy** сохраняются кнопкой **Save**, которая появляется при правке. Новые записи добавляются явно, удаление — одним нажатием значка корзины. Подсказки действий и форматов доступны при наведении. Пустой пароль существующего защищённого входа сохраняет прежний пароль. Ошибки применения не стирают черновик. Занятый при запуске порт показывается ошибкой с кнопкой **Retry**; остальное работает.

Страница **Connections** показывает открытые соединения: адрес, сработавшее правило, маршрут (сервер, Direct, выход, WARP), объём; соединение или все сразу можно закрыть. Текущая скорость — чип в строке статуса, трафик за сеанс — в подробностях сервера.

Строка статуса сверху показывает подключение, Auto и локальный прокси; нажатие на чип открывает его подробности (в широком окне они справа). Уведомления появляются сверху поверх страницы и ничего не сдвигают. **Activity** справа в строке статуса показывает фоновые задачи с прогрессом и кнопкой отмены. Сортировка и фильтры по подписке и протоколу — в заголовках таблицы серверов. Исключения по имени настраиваются на вкладке **Exclude by name** (кнопка с тем же названием есть в заголовке **Servers**).

**Settings** управляет темой, а настройки плагинов (автообновление подписок с вариантом Off, период тестов, автозапуск) показывает в секциях с именами плагинов; **Plugins** — отдельная страница включения и выключения функций, их зависимостей и переходов к настройке. Изменение состава плагинов применяется кнопкой **Restart now**. **Export…** в заголовке Settings сохраняет все настройки и списки в файл `rproxy-config.sqlite3`; **Import…** позволяет выбрать такой файл, проверяет его и предлагает подтвердить замену настроек. В браузере экспорт скачивается на устройство, импорт загружает выбранный локальный файл; в desktop используются системные файловые диалоги. Файл содержит приватные ссылки и ключи. Автоматических резервных копий нет; при неудачном применении импорта программа возвращает прежние настройки, а временная копия удаляется. В **About** кнопка **Check for update** сверяет ядро mihomo с последним выпуском на GitHub; обновление скачивается напрямую или через выбранный сервер, сверяется с опубликованной SHA-256 и должно запуститься до замены; **Use bundled** возвращает комплектное ядро. Закрытие окна оставляет маршрутизацию и расписание работающими. **Open rproxy** возвращает окно, **Quit** в трее завершает приложение и ядро. Цвет иконки: синий — сервер не выбран, зелёный — подключён, красный — ошибка. Если окружение Linux не предоставляет трей (например, GNOME без расширения индикаторов), работа в фоне сохраняется; повторный запуск возвращает окно. В таком окружении в **Settings → General** есть кнопка **Quit rproxy** для полного выхода. Повторный запуск открывает существующее окно; второй desktop-экземпляр того же пользователя не создаётся, даже с другим `--data-dir`. Настройка **Start at login** запускает rproxy в фоне при входе: на Linux — пользовательская XDG-запись, во Flatpak — запрос к Background portal (запись, пропавшая, например, после переустановки, создаётся снова при следующем запуске), на Windows — значение `rproxy` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, на macOS — `~/Library/LaunchAgents/io.github.rproxy.plist`. Если программа переехала, запись при следующем запуске указывает на новый путь. В режиме `web` настройки нет.

В Linux режим **System** получает тему через системный Settings portal (включая GNOME) и реагирует на её изменение без перезапуска. Ручной выбор **Light** или **Dark** имеет приоритет.

**Subscriptions** поддерживает VLESS, Hysteria 2 (`hysteria2://`, `hy2://`), смешанные и Base64-списки. HWID отправляется автоматически при загрузке подписок; отдельной настройки не требуется. Идентификатор случайный, сохраняется в `<data>/plugins/subscriptions/device-id` и не содержит серийных номеров оборудования. Перезапуск и обновление сохраняют его, экспорт конфигурации не переносит идентичность устройства. Если лимит устройств у провайдера исчерпан, приложение показывает отдельную ошибку и сохраняет прежние серверы.

Linux использует оформление окон оконной системы, а на Wayland без серверных декораций — стандартное оформление Adwaita с кнопками окна. Системный буфер обмена включён для X11 и Wayland.

## Своя нода: VLESS inbound

Плагин **VLESS inbound** (по умолчанию выключен; включается в **Settings → Plugins**) принимает клиентов по VLESS поверх REALITY с транспортом XHTTP. Маскировка следует современным советам против DPI:

- **Self steal SNI.** Рукопожатие TLS — это рукопожатие настоящего сайта на вашем домене. Встроенный сайт работает на loopback-порту этой же машины и сам получает сертификат Let's Encrypt (проверка TLS-ALPN-01 проходит через тот же порт 443). Соединение без ключа клиента попадает на этот сайт, поэтому активное зондирование видит обычный веб-сервер. Можно указать и свой сайт (`host:port`, например nginx).
- **XHTTP** вместо голого TCP: данные идут обычными запросами HTTP/2.
- **Без фиксированных интервалов.** Паддинг и время жизни потоков задаются диапазонами. Ссылка клиента просит отпечаток браузера (`fp=chrome`) и явные диапазоны мультиплексирования (XMUX), чтобы клиент не открывал залп рукопожатий к одному SNI. rproxy-клиент применяет те же диапазоны к любой XHTTP-ссылке.
- На ноде включён сниффинг, поэтому доменные правила работают и для клиентов, присылающих IP.

Ссылку и QR-код для каждого клиента показывает страница плагина; удаление клиента отзывает доступ.

**Выходная нода** получается сочетанием настроек, отдельного режима нет:

1. Установите rproxy на сервер. Подписки не добавляйте; лишние плагины (Tests, Start at login и др.) выключите в **Settings → Plugins**.
2. Включите **VLESS inbound**, укажите домен (его A-запись указывает на сервер) и порт 443. Порты ниже 1024 требуют root или `CAP_NET_BIND_SERVICE` для комплектного бинарника mihomo (и для rproxy, если включён ответ на порту 80).
3. В **Routing** добавьте правило `*` → **Direct**, чтобы и трафик самой ноды шёл напрямую, или только **VLESS clients** → **Direct** (кнопка **Send directly** на странице VLESS inbound добавляет его в начало списка). Без него трафик клиентов идёт через выбранный на ноде сервер — так собирается промежуточная нода (каскад).
4. Для публичного управления используйте [защищённый Compose](docker/README.md). Без него запускайте `rproxy web` на `127.0.0.1` и заходите через SSH-туннель (`ssh -L 8080:127.0.0.1:8080 node`).

## Цепочка: Chain exit

Плагин **Chain exit** добавляет второй хоп: это устройство → выбранный сервер (вход) → выходной сервер → интернет. Вход — обычный выбранный вручную или через **Auto select** сервер; выход — один стабильный сервер, который добавляется ссылкой на отдельной странице **Chain exit** и не смешивается с подписками. Сайты видят адрес выхода, а не входа. Если сервер не выбран или выход недоступен, трафик блокируется, а не уходит в обход выхода. Страница и панель подключения показывают путь и задержку через оба хопа; проверка повторяется каждые две минуты.

**Entry** выбирает, как достигается выход: через выбранный сервер или напрямую. **WARP** регистрирует бесплатное устройство Cloudflare WARP (WireGuard с мусорными пакетами AmneziaWG перед рукопожатием) и использует его как **Backup** (если выход недоступен) или как сам выход (**Exit**). Регистрация идёт напрямую, а если Cloudflare недоступен — через выбранный сервер; **Remove** удаляет учётную запись.

## Устройство проекта

Вся функциональность — плагины в `plugins/`, ядро в `crates/kernel`. Устройство и правила проекта — в [AGENTS.md](AGENTS.md) и вложенных `AGENTS.md`: [ядро](crates/kernel/AGENTS.md), [плагины и зоны интерфейса](plugins/AGENTS.md), [дизайн-система](crates/kit/AGENTS.md), [mihomo и TUN](crates/mihomo/AGENTS.md).

| Путь | Назначение |
| --- | --- |
| `src/` | Точка входа: окно, трей, веб-сервер, список плагинов |
| `crates/kernel` | Плагины, состояние, действия, задачи, mihomo, оболочка окна |
| `crates/kit` | Тема, иконки, виджеты egui |
| `crates/mihomo` | Типизированный конфиг и управление ядром |
| `crates/remote` | Интерфейс в браузере: хост рисует, браузер показывает |
| `plugins/` | servers, subscriptions, name-filters, routing, local-proxy, health-checks, chain-exit, vless-inbound, connections, logs, autostart, install-to-server |
| `assets/` | Ядро mihomo, шрифты, логотипы |
| `docker/` | Compose, Caddy, Dockerfile и пример `.env` для VDS |
| `scripts/` | Сборка, упаковка, обслуживание mihomo и проверка Docker-авторизации |
| `.github/workflows/` | Две ручные сборки: desktop и docker |

Плагины включаются и выключаются в **Settings → Plugins**; изменения применяются кнопкой **Restart now**.

## Проверки

Корневой крейт встраивает браузерный клиент из `web/pkg/`, поэтому в свежем checkout
его нужно один раз собрать до Cargo:

```sh
python3 scripts/build.py --web-only
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all --check
# декодирование кадров под wasm32 (нужен Node.js)
CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER=$PWD/.cache/wasm-bindgen/bin/wasm-bindgen-test-runner \
  cargo test --locked -p rproxy-remote --target wasm32-unknown-unknown --test wasm_decode
```

Сквозные тесты (`tests/e2e.rs`, `tests/node.rs`) запускают настоящий mihomo на временных локальных адресах: форматы подписок через цепочку плагинов, загрузку и обновление, выбор сервера, маршруты, отклонение правки слушателя на занятый порт, HTTP/SOCKS5-авторизацию, проверки через изолированный маршрут, автовыбор, сохранение после перезапуска ядра, VLESS-ноду с клиентом (REALITY + XHTTP, сайт-приманка для зондов) и цепочку через выходной сервер. `tests/features.rs` проверяет соединения, резервные копии и TUN без прав; с `--ignored` — гео-списки и WARP (нужен интернет; `RPROXY_TEST_UPSTREAM=host:port` задаёт SOCKS5-вход, если Cloudflare напрямую недоступен). `crates/kernel/tests/core_update.rs` (`--ignored`) обновляет ядро с GitHub и возвращает комплектное. `crates/kernel/tests` проверяют механику ядра на тестовых плагинах, `crates/remote/tests` — передачу кадров интерфейса, в том числе декодирование под wasm32.

## Сборки приложения

**Actions → release → Run workflow** собирает WASM один раз, затем параллельно
запускает шесть нативных сборок. Workflow запускается только вручную;
push, pull request и создание тега сборку не запускают. Тесты и Clippy
остаются локальными командами. Публикация GitHub Release не выполняется.

В Artifacts все пакеты лежат одним списком, каждый — отдельным zip с именем
пакета: `rproxy-<версия>-linux-x64.AppImage`, `rproxy-<версия>-windows-arm64-setup.exe`,
`rproxy-<версия>-windows-x64-portable` (папка portable-версии) и т. д.
Промежуточных артефактов нет: WASM передаётся между jobs через кэш.

Кэши: WASM кэшируется по хешу `crates/remote`, `Cargo.lock`, `Cargo.toml` и
`rust-toolchain.toml` — если они не менялись, WASM не пересобирается. Зависимости
Rust кэширует `Swatinem/rust-cache` отдельно для каждой целевой платформы; кэш
сохраняют только запуски из `master`, чтобы не переполнять лимит кэша GitHub.
Финальная линковка (fat LTO) не кэшируется. wasm-bindgen ставится готовым
бинарником той же версии, что в `Cargo.lock`.

| ОС | Архитектуры | Пакеты |
| --- | --- | --- |
| Windows | x64, ARM64 | NSIS setup.exe, portable-папка |
| Linux | x64, ARM64 | AppImage, Flatpak |
| macOS | Intel x64, Apple Silicon ARM64 | DMG |

Версия берётся из корневого Cargo.toml, Rust — из rust-toolchain.toml, версия
wasm-bindgen — из Cargo.lock, mihomo — из `assets/mihomo/manifest.json`.
Каждый job сборки берёт **свой** бинарник mihomo из `assets/mihomo/<os>/<arch>/`,
проверяет его SHA-256 по `manifest.json`, компилирует программу для
`CARGO_BUILD_TARGET` и упаковывает её. Checkout получает только ядро выбранной
платформы. Обе сборки macOS идут на Apple Silicon runner, Intel — кросс-компиляцией.
Сборки Linux используют Ubuntu 24.04 для совместимости с glibc 2.39+;
Flatpak использует runtime 26.08.
AppImage использует графические библиотеки установленного Linux-десктопа
(X11/Wayland, xkbcommon, EGL/OpenGL); Flatpak получает их из runtime.

Windows setup устанавливается текущему пользователю без администратора.
Portable-папка хранит `data` рядом с бинарником
(маркер `portable.txt`). Переносите portable-профиль вместе с программой.

Во всех готовых сборках, включая Docker, `rproxy` и `mihomo` лежат рядом
(в Windows — `rproxy.exe` и `mihomo.exe`). Программа ищет ядро одинаково на всех ОС.
Упаковщик размещает лицензию в `licenses/mihomo/LICENSE` внутри каталога ресурсов пакета.

DMG содержит приложение для переноса в Applications и ad-hoc подпись,
не Developer ID/notarization. Внутри `.app` исполняемые файлы лежат в `Contents/MacOS`,
лицензия ядра — в `Contents/Resources/licenses/mihomo/LICENSE`.
Сначала подписывается ядро, затем весь `.app`. Windows-пакеты также не имеют сертификата подписи:
ОС может потребовать явного разрешения запуска скачанного приложения.
Трей и работа в фоне доступны на Linux, macOS и Windows; при запуске `rproxy background` программа до 10 с ждёт появления трея,
прежде чем показать окно. Автозапуск работает во всех desktop-пакетах; AppImage записывает путь самого файла AppImage
(`APPIMAGE` учитывается, только если процесс действительно запущен из этого AppImage).

Системный прокси и TUN. Изменённые системные настройки записываются в `<профиль>/plugins/local-proxy/system-proxy.json`;
после аварии, выхода из сеанса или принудительного завершения следующий запуск возвращает значения, которые всё ещё
равны записанным rproxy. На Windows используется WinINet `INTERNET_OPTION_PER_CONNECTION_OPTION` (обновляет и
`Connections\DefaultConnectionSettings`). При включении TUN rproxy сам открывает системный запрос прав:
Polkit (`pkexec`) на Linux, диалог администратора на macOS, UAC на Windows. С правами администратора
запускается только ядро mihomo (под внутренним `rproxy --core-supervisor`); интерфейс остаётся с обычными
правами. Права действуют, пока работает это ядро: каждое включение TUN и каждый перезапуск ядра с TUN
спрашивают их снова. На время запроса прокси-порты недоступны: ядро одно и перезапускается с новыми правами.
При отказе ядро запускается без туннеля, а настройка TUN остаётся выключенной. Если TUN был сохранён
ранее, отказ при запуске программы оставляет обычные порты рабочими и показывает ошибку у TUN; для повтора
выключите и включите TUN.

Во Flatpak запрос идёт через `flatpak-spawn --host` и Polkit: ядро работает на хосте, для этого пакет
содержит разрешение `--talk-name=org.freedesktop.Flatpak` (запуск процессов на хосте); на хосте нужны
Polkit и агент аутентификации рабочего стола. Системный прокси во Flatpak по-прежнему недоступен; в Docker
не используются ни системный прокси, ни TUN. AppImage распаковывать не требуется. Ядро останавливается при
закрытии или аварии приложения. Постоянные setuid-копии, службы и `setcap` не создаются.
Установщик и деинсталлятор Windows
просят закрыть запущенный rproxy перед заменой файлов. `rproxy web`, запущенный из консоли Windows, печатает адрес
в эту консоль и останавливается по Ctrl+C.

Обновлённое ядро в `<профиль>/core/bin/` (версия в `mihomo.version`) используется, только пока оно новее
комплектного; если оно не запускается, rproxy удаляет его и запускает комплектное.

Профиль установленной версии: `%LOCALAPPDATA%\rproxy` на Windows,
`~/Library/Application Support/rproxy` на macOS, `$XDG_DATA_HOME/rproxy`
(обычно `~/.local/share/rproxy`) на Linux. Путь можно переопределить переменной `RPROXY_DATA_DIR`.
Удаление Windows-программы сохраняет профиль.

Ядро запускается через внутренний служебный режим того же `rproxy`: закрытие
канала владельца, в том числе после аварии приложения, завершает и дожидается
выхода mihomo. На Windows дополнительно используется Job Object, созданный
до запуска ядра. Защита не рассчитана на отдельное принудительное убийство
самого служебного процесса на Unix. Desktop использует общий пользовательский
замок, а web-экземпляры — отдельный замок на каталог данных. Flatpak получает
доступ только к общей папке замка `xdg-run/rproxy`, а не к чужим профилям.

### Локальная сборка

Нужны Python 3.11+, Rust из rust-toolchain.toml (rustup ставит его сам) и
системный C toolchain (Windows: MSVC, macOS: Xcode command-line tools, Linux: GCC).
Библиотеки X11/Wayland/EGL для сборки не нужны: окно загружает их при запуске.

```sh
python3 scripts/mihomo.py
python3 scripts/build.py --release
```

В репозитории уже есть все шесть бинарников mihomo. Проверка не требует сети;
при локальном запуске нужный бинарник выбирается автоматически.
На Windows используйте `python`. Все скрипты сборки написаны на Python.
`--native-only` пропускает сборку WASM, `--web-only` собирает только WASM.
`--no-default-features` даёт серверный бинарник без eframe, X11, Wayland и трея.

Скрипт `scripts/package.py` запускается **на целевой ОС и архитектуре** после
release-сборки. Нужные инструменты упаковки (Linux: flatpak, flatpak-builder,
librsvg2-common; Windows: NSIS) устанавливает release.yml.
`librsvg2-common` нужен Flatpak для чтения SVG-иконки при экспорте; PNG-иконка
512 px (`assets/logos/rproxy-blue-512.png`) отрендерена заранее из
`rproxy-blue.svg` — после правки SVG её нужно обновить:
`magick -density 384 -background none RSVG:assets/logos/rproxy-blue.svg PNG32:assets/logos/rproxy-blue-512.png`.

Вся сборочная логика находится в четырёх Python-файлах:

- `scripts/build.py` — компиляция WASM и приложения. Локально утилита wasm-bindgen
  ставится в `.cache/wasm-bindgen`, отдельно от очищаемого Cargo-кэша; в CI она
  уже лежит в PATH.
- `scripts/package.py` — создание пакетов, по одной функции на ОС. Шаблоны
  установщика NSIS и Linux desktop entry лежат в `scripts/packaging/`; манифест
  Flatpak и macOS Info.plist собираются в коде; промежуточные файлы генерируются
  в игнорируемом `dist/`. linuxdeploy закреплён
  на релизе `1-alpha-20251107-1` и проверяется по SHA-256.
- `scripts/mihomo.py` — проверка и выбор комплектного ядра; `--update` обновляет
  бинарники по закреплённым URL и хешам в `assets/mihomo/manifest.json`.
- `scripts/test-docker-auth.py` — ручная сквозная проверка серверной установки.
