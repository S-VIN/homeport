В проекте нужно вести список правил. Если пользователь что-то просит, но это похоже на правило проекта, то в интерактивной форме спроси, нужно ли его добавлять в правила проекта в AGENTS.md. 

В правила нужно добавлять только общую информацию, которая может пригодиться в будущем, кратко. Если правило специфично для какой-то части проекта, то добавлять его нужно в AGENTS.md этой части проекта. То есть нужно поддерживать древовидную структуру среди AGENTS.md файлов проекта.

Правила можно делить по категориям и актуализировать по ходу работы с согласия пользователя. Пользователь может попросить сделать что-то, что противоречит правилам. В этом случае нужно уточнить, менять ли правило или нет.

AGENTS.md файлы не должны привышать 100 строчек. Если превышают, то нужно проревьюить документ и предложить пользователю способы, как его сжать.

## Что это

rproxy — менеджер прокси на mihomo для десктопа и VDS. Один процесс владеет ядром приложения, плагинами и mihomo. Окно и каждая вкладка браузера рисуют один и тот же egui-интерфейс: код UI выполняется на хосте, браузер только рисует и шлёт ввод. В коде плагинов нет клиента, сервера и протокола.

## Структура

```text
src/             приложение: CLI, окно eframe, трей, веб-сервер, каталог плагинов (catalog())
plugins/*        вся функциональность — plugins/AGENTS.md
crates/kernel    плагины, State/Op/Event/Slot, транзакции, SQLite, задачи, mihomo как сервис,
                 оболочка окна и её зоны, сессии UI, Host — crates/kernel/AGENTS.md
crates/kit       дизайн-система egui без домена — crates/kit/AGENTS.md
crates/mihomo    типизированный конфиг, процесс ядра, супервизор, TUN — crates/mihomo/AGENTS.md
crates/remote    удалённый egui: хост-стример и wasm-клиент — crates/remote/AGENTS.md
crates/derive    #[derive(Table)] для SQLite
assets/          ядро mihomo, шрифты, логотипы
docker/          Dockerfile, Compose, Caddy (docker/README.md)
scripts/         сборка (build.py), упаковка (package.py), обслуживание mihomo
web/             страница wasm-клиента
tests/           сквозные тесты с настоящим mihomo
```

Ядро и kit не зависят от плагинов. Плагин зависит от `rproxy-kernel` и от крейтов плагинов, чьи типы использует (`requires` в манифесте).

## Согласование

- Любое изменение архитектуры или понятий (API ядра и плагинов: `Setup`, `Cx`, ops, виды состояния, границы плагинов) и любое изменение зависимостей (добавить, убрать, заменить крейт, выровнять версии) — только после явного согласия пользователя. Предлагай варианты с рекомендацией. Локальные правки внутри функции можно делать сразу.
- Не уменьшай функциональность и не добавляй лишних абстракций. Главный приоритет — простой код плагинов: приложение растёт через плагины.
- Новую фичу сначала размещай в существующем плагине там, где её будет искать пользователь; новый крейт плагина — после согласования.
- Список планируемых плагинов в отдельный файл не пишется.
- Безопасность веб-доступа (авторизация, проверка Origin, скрытие секретов) отложена: не трать на неё время без просьбы.
- `~/Documents/x-proxy-router` — источник требований, а не кода: его решения не копируются.

## Совместимость (до релиза)

- Приложение не зарелижено: ломать обратную совместимость разрешено и рекомендуется (CLI, формат данных, схема БД, настройки, API плагинов), если это делает код проще. Слои совместимости, алиасы и переходные пути не добавляются.
- Миграций БД нет: схему меняют прямо в создании таблиц и настроек. Старые профили можно не поддерживать. Миграции появятся после релиза.

## Продукт

- Пользовательский текст на английском. Названия понятий — привычные для прокси-приложений (v2rayN, Clash Verge, Hiddify, NekoBox); одно имя на понятие везде (вкладка, плагин, настройка, тост).
- Удаление строк — одним нажатием, без подтверждения. Поиска по списку серверов нет. Не предлагай их снова.
- Плагины работают на Linux, Windows, macOS и в Docker, если `platforms` не говорит иного (plugins/AGENTS.md).
- База — `rproxy-plugins.sqlite3`; старая `rproxy.sqlite3` не переносится.

## Проверки

```sh
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
```

UI: `python3 scripts/build.py`, затем `RPROXY_LISTEN=127.0.0.1:18080 RPROXY_DATA_DIR=<tmp> rproxy web` и браузер (crates/kit/AGENTS.md → «Проверка»).

Тесты: `crates/kernel/tests` — механика ядра на тестовых плагинах; `tests/e2e.rs` — настоящий mihomo (форматы, загрузка, выбор, маршруты, слушатели, проверки, автовыбор, перезапуск); `tests/features.rs`, `regressions.rs`, `ui_regressions.rs` — сценарии приложения; `tests/lifecycle.rs`, `tunnel.rs` — жизнь процесса ядра и TUN; `tests/node.rs` — узел VLESS и цепочка через него; `crates/remote/tests` — кадры по проводу и декодирование под wasm32.
