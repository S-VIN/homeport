# Deploy server

Вкладка **Deploy server** в настольном клиенте устанавливает включённый в проект
Docker Compose-стек по SSH. Нужны адрес сервера, логин и пароль SSH; пользователь
должен быть root или иметь sudo с тем же паролем (без требования TTY).

По умолчанию домен — `auto`: публичный IPv4 SSH-адрес используется в
`panel.<ip-with-dashes>.sslip.io` и `auth.<ip-with-dashes>.sslip.io`.
Регистрация и DNS-токен не нужны. Для IPv6 укажите свой домен. Для своего домена
создайте записи `panel.<domain>` и `auth.<domain>` на адрес сервера.
Доступность auto зависит от sslip.io и лимитов выдачи сертификатов ACME.

В Installation settings настраиваются SSH/HTTPS/VLESS и внутренние порты,
каталог установки, образ rproxy, логин/пароль панели и ACME email.
Незаданный пароль панели генерируется случайно. Откройте во внешнем firewall
TCP 80, выбранные HTTPS/VLESS порты и SSH. Установщик не меняет firewall.
HTTPS по умолчанию 8443, VLESS — 443. VLESS/REALITY использует HTTPS-панель
Caddy как TLS-сайт, поэтому работает и с другим выбранным VLESS-портом.

Плагин создаёт новый независимый профиль: VLESS/REALITY/XHTTP, случайные ключи
и UUID клиента, маршрут `* → Direct`. Настройки и подписки клиента не копируются.
После установки доступны ссылки на панель и VLESS, кнопки копирования пароля
панели и **Add to client** (добавляет ссылку в Subscriptions).
Ссылки и пароль панели хранятся в локальной базе rproxy и попадают в экспорт
настроек. SSH-пароль не сохраняется. Ключ SSH закрепляется при первом соединении
в `plugins/deploy-server/known_hosts`; изменение ключа блокирует соединение.

Поддерживаются Linux-серверы amd64/arm64. При установленном Docker проверяется
Compose; при отсутствии устанавливается пакет Compose. Для Debian/Ubuntu,
Fedora/RHEL-подобных используется официальный установщик Docker; Alpine,
Arch и openSUSE используют пакеты дистрибутива. Неизвестная/устаревшая ОС,
закрытые порты, отсутствие sudo или недоступный образ дают окно ошибки.
Образ GHCR должен быть публичным либо сервер должен уже иметь Docker login.

Существующий каталог установки никогда не перезаписывается. При ошибке после
подготовки профиль и ссылки сохраняются для диагностики. Установка не имеет
кнопки отмены: удалённый пакетный менеджер нельзя безопасно оборвать.
Для диагностики: `cd <install-dir> && docker compose logs --tail=100`.
Для удаления: `docker compose down`, затем удаление выбранного каталога.
Docker и системные пакеты автоматически не удаляются.

Проверки:

```sh
cargo test -p plugin-deploy-server --lib
cargo clippy -p plugin-deploy-server --all-targets -- -D warnings
```

Опциональный реальный тест (меняет сервер): пример `install` читает
`DEPLOY_TEST_HOST` и `DEPLOY_TEST_PASSWORD`, использует `/srv/rproxy-plugin-test`.
Его результат содержит секреты в `/tmp/rproxy-deploy-harness/result.json` (0600).
Очистка сервера после такого теста — обязанность запускающего.
