# Install to server

Страница **Install to server** ставит на свой Linux-сервер rproxy с веб-панелью
(Compose-стек из `docker/`) по SSH. Только в настольных сборках. Входы (VLESS) плагин
не знает: их включают и настраивают в панели установленного сервера.

## Что вводит пользователь

Обязательно: адрес сервера, SSH-логин (root или пользователь с sudo, пароль sudo —
тот же) и SSH-пароль. Сразу в форме: логин и пароль панели (пустой пароль —
случайный) и переключатель **Turn off IPv6** (по умолчанию включён).

Под **More settings**: домен, email для сертификата, SSH-порт, порт панели (8443),
папка установки (`/srv/rproxy`), образ контейнера.

- Домен пустой — берётся `<ip-через-дефисы>.sslip.io`: записи DNS и регистрация не
  нужны, но серверу нужен публичный IPv4. Свой домен: записи `panel.<домен>` и
  `auth.<домен>` должны указывать на сервер.
- **Turn off IPv6** записывает `/etc/sysctl.d/99-rproxy-disable-ipv6.conf` и
  применяет его сразу: трафик уходит с сервера только по IPv4. При подключении по
  IPv6 установка с этой настройкой не начинается.
- Внутренние порты панели выбираются на сервере сами (первые свободные от 20800).
- Пароль панели и email не могут содержать `'` и `\` (они пишутся в `.env`).

## Ход установки

Кнопка **Install** запускает задачу: прогресс и текущий шаг видны рядом с кнопкой
и в Activity. Шаги приходят от `install.sh` строками `::step::…`, причина ошибки —
строкой `::error::…`; без неё показывается конец вывода сервера.

1. SSH-подключение по паролю. Ключ сервера запоминается при первом подключении
   в `plugins/install-to-server/known_hosts`; изменившийся ключ блокирует подключение.
2. Профиль нового сервера собирается через `rproxy_kernel::configuration::Profile`:
   только правило `* → Direct` (сервер — выход). Настройки этого устройства на
   сервер не попадают.
3. Файлы загружаются во временную папку (`mktemp`), `install.sh` запускается от
   root (через `sudo -S`, если логин не root). SSH-пароль нигде не сохраняется.
4. Скрипт проверяет систему (Linux amd64/arm64, свободные 80 и порт панели, папки
   ещё нет), ставит curl, Docker и Compose при их отсутствии, запускает стек и ждёт
   HTTPS-сертификат.

Откройте во внешнем firewall TCP 80, порт панели и SSH (и порт VLESS, когда включите его в панели): установщик
firewall не трогает. Образ должен быть публичным или сервер — уже залогинен в реестр.

## Результат и ошибки

- Успех: сервер появляется в **Installed servers**. Кнопки строки: скопировать
  пароль панели, открыть панель. VLESS включается в панели (страница VLESS
  inbound), ссылку клиента берут там же. Пароль панели хранится в базе rproxy и
  попадает в экспорт настроек.
- Ошибка на сервере: скрипт сам убирает за собой (контейнеры, папку, настройку
  IPv6), запись не остаётся — установку можно просто повторить. Установленные
  Docker и пакеты остаются.
- Обрыв связи, Stop или таймаут (30 минут) во время установки: исход на сервере
  неизвестен, поэтому запись остаётся с пометкой о прерванной установке — панель
  можно открыть и проверить, либо удалить запись и поставить заново.
- Удаление строки убирает только запись на этом устройстве. Сервер удаляется
  вручную: `cd <папка> && docker compose down`, затем удалить папку и
  `/etc/sysctl.d/99-rproxy-disable-ipv6.conf`.
